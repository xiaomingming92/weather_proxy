### 数据库现状

当前使用统一的 `WeatherData` 表，通过 `appType` 字段区分：

```prisma
model WeatherData {
  id           Int      @id @default(autoincrement())
  cityId       String
  dataType     String
  appType      String   @default("unknown")  // weathertv / weatherwidget
  xmlData      String   @db.Text
  // ...
  @@unique([cityId, dataType, appType])
}
```

**问题**：
- 缓存策略不同（HTC 和 ZTE 的缓存时长需求不同）
- 数据结构不同（XML 格式完全不同）
- 查询时需要额外过滤 `appType`

### Phase 2: 数据库拆分

**目标**：为 HTC 和 ZTE 创建独立的缓存表

**新 Schema 设计**：

```prisma
// ZTE 缓存表
model ZteWeatherCache {
  id            Int      @id @default(autoincrement())
  cityId        String
  dataType      String   // ztewidgetsk, ztewidgetcf, ztev3widgetskall, etc.
  xmlData       String   @db.Text
  timestamp     BigInt
  expiresAt     BigInt
  cacheDuration Int      @default(30)
  createdAt     BigInt
  updatedAt     BigInt
  
  @@unique([cityId, dataType])
  @@index([expiresAt])
}

// HTC 缓存表
model HtcWeatherCache {
  id            Int      @id @default(autoincrement())
  cityId        String
  endpoint      String   // forecast-data_v3, city-find, etc.
  xmlData       String   @db.Text
  timestamp     BigInt
  expiresAt     BigInt
  cacheDuration Int      @default(30)
  createdAt     BigInt
  updatedAt     BigInt
  
  @@unique([cityId, endpoint])
  @@index([expiresAt])
}

// 城市表（共用）
model City {
  id        Int      @id @default(autoincrement())
  name      String   @unique
  cityId    String   @unique
  stationId String?
  longitude String?
  latitude  String?
  postcode  String?
  sunrise   String?
  sunset    String?
  createdAt BigInt
  updatedAt BigInt
}

// ZTE 缓存策略配置
model ZteCachePolicy {
  id          Int      @id @default(autoincrement())
  dataType    String   @unique
  duration    Int
  description String?
  createdAt   BigInt
  updatedAt   BigInt
}

// HTC 缓存策略配置
model HtcCachePolicy {
  id          Int      @id @default(autoincrement())
  endpoint    String   @unique
  duration    Int
  description String?
  createdAt   BigInt
  updatedAt   BigInt
}
```

**缓存服务拆分**：

```
src/services/
├── cache/
│   ├── zte-cache.ts      # ZTE 专用缓存服务
│   ├── htc-cache.ts      # HTC 专用缓存服务
│   └── city-cache.ts     # 城市信息缓存（共用）
```

## 风险与回滚

### 风险

1. **导入路径错误**：可能导致编译失败
2. **缓存数据丢失**：迁移后旧缓存数据无法访问
3. **路由行为变化**：校验器可能拒绝之前合法的请求

### 缓解措施

1. **编译检查**：每次修改后运行 `npm run build` 检查
2. **数据备份**：迁移前备份数据库
3. **灰度测试**：先在测试环境验证

### 回滚方案

如果出现问题，可以：
1. 回滚到上一个 Git commit
2. 恢复旧的数据库 Schema
3. 恢复旧的缓存数据
